# Taksi — учебный сервис такси

Backend-сервис на **Java 21 + Spring Boot 3.5 + PostgreSQL 17**. Он реализует алгоритм из курсовой
«Как работает Яндекс.Такси» и отвечает на три вопроса презентации:

1. **Сколько платит пассажир?** Цена `P = S + k × (c_t × T + c_d × D) + O` с коэффициентом спроса.
2. **Какой водитель получит заказ?** Буферный подбор венгерским алгоритмом: минимум суммарной подачи.
3. **Сколько остаётся водителю?** Цена минус комиссии, налоги и топливо.

Города: **Бишкек** (сом, KGS) и **Москва** (рубли, RUB, числа со слайдов).

> Это учебная модель. Точные формулы Яндекс не публикует. Ставки взяты из открытых источников
> (см. [Источники](#источники)), часть значений условная — это отмечено в миграциях.

## Быстрый старт

Нужно: JDK 21+ (проверено на 25), Maven 3.9+, PostgreSQL 15+ (проверено на 17).

```bash
# 1. Базы данных: рабочая и тестовая
createdb taxi
createdb taxi_test

# 2. Запуск с демо-водителями (Бишкек и Москва)
mvn spring-boot:run -Dspring-boot.run.profiles=demo

# 3. Swagger UI
open http://localhost:8080/swagger-ui.html
```

Схема создаётся автоматически (Flyway, миграции `V1`–`V6`). Подключение к БД — через переменные окружения:

| Переменная | По умолчанию |
|---|---|
| `DB_URL` | `jdbc:postgresql://localhost:5432/taxi` |
| `DB_USERNAME` | текущий пользователь ОС (`$USER`) |
| `DB_PASSWORD` | пусто |
| `TEST_DB_URL` | `jdbc:postgresql://localhost:5432/taxi_test` |

Тесты:

```bash
mvn clean verify        # 653 теста, нужна база taxi_test (тесты очищают в ней таблицы!)
```

## Восемь шагов алгоритма (слайд 4) → API

| Шаг | Что происходит | API |
|---|---|---|
| 1. Маршрут | Точки А и Б, город определяется по точке А | `POST /api/v1/quotes` |
| 2. Цена | Тариф, спрос k, опции, прогноз подачи; цена фиксируется на 5 мин | `POST /api/v1/quotes` |
| 3. Заказ | Пассажир соглашается с ценой (идемпотентно по `Idempotency-Key`) | `POST /api/v1/orders` |
| 4. Поиск водителя | Раунд раз в 5 с: венгерский алгоритм; отказ → поиск снова | автоматически, `POST /api/v1/dispatch/run` |
| 5. Подача | Водитель принимает, едет, прибыл | `POST /api/v1/driver/orders/{id}/accept`, `/arrive` |
| 6. Поездка | Начало и завершение | `/start`, `/complete` |
| 7. Оплата | Пассажир платит цену из quote | при `/complete` |
| 8. Расчёт | Комиссии, налоги, топливо, остаток водителю | `GET /api/v1/driver/orders/{id}/settlement` |

Справочники: `GET /api/v1/cities`, `GET /api/v1/tariffs?city=BISHKEK`.
Регистрация пассажира: `POST /api/v1/passengers`.

### Статусы заказа

```
SEARCHING ─assign─▶ DRIVER_ASSIGNED ─accept─▶ DRIVER_EN_ROUTE ─arrive─▶ DRIVER_ARRIVED ─start─▶ IN_PROGRESS ─complete─▶ COMPLETED
    ▲                    │ decline / 60 с без ответа        │ отмена водителем       │
    └────────────────────┴──────────────────────────────────┴───────────────────────┘
SEARCHING … DRIVER_ARRIVED ─отмена пассажиром─▶ CANCELLED        (IN_PROGRESS отменить нельзя → 409)
```

## Формулы (наша модель)

### Цена — слайды 5–6

```
P = S + k × (c_t × T + c_d × D) + O
```

| Символ | Что это | Откуда |
|---|---|---|
| S | Подача (+ доплата за дальнюю подачу > 6,7 мин или > 3,5 км) | тариф города |
| k | Коэффициент спроса | см. ниже |
| T, D | Минуты и км: D = прямая × 1,3; T = D / 24 км/ч | `taksi.route.*` |
| c_t, c_d | Цена минуты и километра | тариф города |
| O | Опции (детское кресло, животное) | справочник опций города |

Итог округляется до целых единиц валюты (HALF_UP). Слайд 10: `189 + 1,12 × (13 × 25 + 13 × 10) = 698,60 → 699 ₽`.

### Коэффициент спроса — слайд 7

```
r = пины / свободные машины;   k = 1 + 0,4 × (r − 1),   1 ≤ k ≤ 3
```

Пин — запрос цены из точки А за последние 10 минут. Зона — ячейка 0,01° вместе с соседями 3×3
(сглаживание). Если машин нет, k = 3.

### Подбор водителя — слайд 8

Матрица «заказ × водитель» — время подачи в минутах. Пара запрещена, если подача больше 10 км
или водитель уже отказался от этого заказа. Венгерский алгоритм минимизирует сумму, а при
нехватке водителей сначала обслуживает как можно больше заказов.

| Пример | Жадный выбор | Венгерский |
|---|---|---|
| Слайд 8: `[[2,3],[3,9]]` | 11 мин | **6 мин** |

### Доход водителя — слайды 9–10

```
Доход = Цена − Цена × (сервис + парк + налог + взносы) − Топливо
```

| | Москва | Бишкек |
|---|---|---|
| Сервис | 22,37% Эконом / 25,42% Комфорт | 16% / 17% |
| Налог | НПД 4% | подоходный 1% |
| Страховые взносы | — | 1% |
| Парк | ставка парка водителя (демо 3%) | то же |
| Топливо | 5,1852 ₽/км (70 ₽ / 13,5 км) | 5,5 сом/км (условно) |

Каждая статья округляется до копеек, водителю достаётся остаток: сумма статей равна цене точно
(это закреплено CHECK-ограничением в БД).
Слайд 10: `699 → сервис 156,37 · парк 20,97 · НПД 27,96 · топливо 70,00 · водителю 423,70 (60,6%)`.

## Сценарий для защиты (curl)

Нужно, чтобы приложение было запущено с профилем `demo`. Весь сценарий одной командой — `./scripts/demo.sh`.

```bash
U=http://localhost:8080/api/v1; H='Content-Type: application/json'

# Слайд 10 — калькулятор (ничего не записывает)
curl "$U/settlements/preview?city=MOSCOW&tariff=ECONOM&price=699&km=13.5&parkRate=0.03"

# 1–2. Пассажир и цена (Бишкек: площадь Ала-Тоо → Asia Mall)
curl -X POST $U/passengers -H "$H" -d '{"fullName":"Айгуль","phone":"+996555000111"}'      # → id
curl -X POST $U/quotes -H "$H" -d '{"from":{"lat":42.8765,"lon":74.6037},
  "to":{"lat":42.8559,"lon":74.5860},"tariff":"ECONOM"}'                                     # → quoteId, total

# 3. Заказ
curl -X POST $U/orders -H "$H" -H "X-Passenger-Id: <id>" -H "Idempotency-Key: demo-1" \
     -d '{"quoteId":"<quoteId>"}'                                                            # → orderId

# 4. Через ~5 с диспетчер назначит водителя (или сразу: POST $U/dispatch/run)
curl $U/orders/<orderId> -H "X-Passenger-Id: <id>"                                          # → driver.id

# 5–6. Водитель (не дольше 60 с на accept)
for a in accept arrive start complete; do
  curl -X POST $U/driver/orders/<orderId>/$a -H "X-Driver-Id: <driverId>"; done

# 7–8. Куда ушли деньги
curl $U/driver/orders/<orderId>/settlement -H "X-Driver-Id: <driverId>"
curl $U/driver/earnings -H "X-Driver-Id: <driverId>"
```

## Архитектура

```
ru.taksi
├── geo          GeoPoint (гаверсинус), GridCell (зоны спроса)
├── pricing      PriceCalculator, SurgeCalculator, RouteEstimator   ← чистые функции, unit-тесты по слайдам
├── city         города и зоны обслуживания
├── tariff       тарифы и опции по городам
├── quote        QuoteService — шаги 1–2, фиксация цены
├── passenger    регистрация
├── driver       Driver, DriverService — линия, координаты
├── order        RideOrder + OrderAction (машина состояний), OrderService — шаги 3–6
├── dispatch     HungarianAlgorithm, DispatchService, DispatchScheduler — шаг 4
├── settlement   SettlementCalculator, SettlementService — шаги 7–8
└── api          единый формат ошибок (RFC 7807 + поле code)
```

Формат ошибки:

```json
{"status":422,"title":"Unprocessable Entity","detail":"Точка А вне зоны обслуживания …","code":"OUTSIDE_SERVICE_AREA"}
```

### Ключевые инварианты

| Инвариант | Где закреплён |
|---|---|
| Один quote → не больше одного заказа | `UNIQUE (quote_id)` |
| У пассажира и у водителя не больше одного активного заказа | частичные `UNIQUE`-индексы |
| В поиске водителя нет; после назначения он есть | `CHECK` в `ride_order` |
| Повтор `POST /orders` с тем же ключом не создаёт дубль | `UNIQUE (passenger_id, idempotency_key)` + повторное чтение |
| Зоны городов не пересекаются | `EXCLUDE USING gist` |
| Сумма статей расчёта = цена | `CHECK` в `ride_settlement` |
| Завершение и расчёт атомарны | одна транзакция (`Propagation.MANDATORY`) |
| Переходы статусов не гоняются | `SELECT … FOR UPDATE`: сначала заказ, потом водитель |

## Настройки (`application.yml`, префикс `taksi.`)

| Параметр | Значение | Смысл |
|---|---|---|
| `route.avg-speed-kmh` | 24 | средняя скорость для T и подачи |
| `route.road-factor` | 1,3 | дорога длиннее прямой |
| `surge.alpha`, `surge.k-max` | 0,4 / 3 | формула k |
| `surge.pin-window` | 10m | окно учёта пинов |
| `pickup.long-pickup-min` / `-km` | 6,7 / 3,5 | порог дальней подачи |
| `quote.ttl` | 5m | срок действия цены |
| `dispatch.interval` | 5s | буфер подбора |
| `dispatch.max-pickup-km` | 10 | максимум подачи |
| `dispatch.offer-timeout` | 60s | время на принятие заказа |
| `dispatch.enabled` | true | фоновые раунды (в тестах выключены) |

Ставки комиссий, налогов и топлива хранятся в БД (`tariff`, `city`, `taxi_park`) и задаются миграциями.

## Ограничения

| Ограничение | Последствие |
|---|---|
| **Нет аутентификации.** Личность передаётся заголовками `X-Passenger-Id` / `X-Driver-Id` | Любой может действовать от имени любого пользователя. **Не выкладывать в интернет.** |
| `POST /dispatch/run` и Swagger открыты всем | Служебный метод доступен без прав |
| Нет ограничения частоты запросов | Массовыми `POST /quotes` можно поднять k в зоне |
| Расстояние по прямой × 1,3, без карт и пробок | Прогноз грубее реального |
| Зона города — прямоугольник | В Бишкеке захватывает пригороды |
| Оплата условная (без шлюза, наличные и карта не различаются) | Шаг 7 — запись факта |
| НПД всегда 4% (без 6% для корпоративных клиентов) | — |
| Заказ ищет водителя бесконечно | Нет автоотмены «водитель не найден» |
| Ставки Бишкека: комиссия — по СМИ, топливо — условно | Цифры для учебного примера |
